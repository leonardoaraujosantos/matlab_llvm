# Python Codegen Spec

## Purpose
Documents the observed behavior of `matlabc`'s `-emit-python` backend, which translates the lowered MLIR module to a self-contained NumPy-backed Python module. The emitter reuses the shared lowering pipeline up through I/O lowering, then prints Python that reads as a natural translation of the MATLAB source, importing a NumPy-backed runtime shim for MATLAB-semantics helpers. The backend is treated as experimental, with numerically sensitive cases skipped in the test lane.

## Requirements

### Requirement: Emit self-contained Python source
The system SHALL, in `-emit-python` mode, translate the lowered MLIR module to a Python module and write it to stdout with a generated-file header.

#### Scenario: Emitting Python for a script
- **WHEN** a user runs `matlabc -emit-python foo.m > foo.py`
- **THEN** the system SHALL print a self-contained Python module beginning with a `Generated by matlabc -emit-python` header (doc: docs/emit_python.md; src: lib/MLIR/Passes/EmitPython.cpp)

### Requirement: Conditional runtime and NumPy imports
The system SHALL include `import matlab_runtime as rt` and/or `import numpy as np` only when the emitted body references those symbols.

#### Scenario: Pure-arithmetic program
- **WHEN** the program uses only scalar arithmetic and `print`
- **THEN** the system SHALL emit no `rt` or `np` import (doc: docs/emit_python.md; src: lib/MLIR/Passes/EmitPython.cpp)

#### Scenario: Matrix program
- **WHEN** the program uses matrices
- **THEN** the system SHALL emit `import numpy as np` and map matrices to `np.array(...).reshape(...)` (doc: docs/emit_python.md)

### Requirement: NumPy-backed matrix semantics
The system SHALL map MATLAB matrix operations to NumPy equivalents so array arithmetic and linear algebra match MATLAB semantics.

#### Scenario: Matrix operators
- **WHEN** the program uses `*`, `.*`, and `'` on matrices
- **THEN** the system SHALL emit `@` (matmul), `*` (element-wise), and `.T` (transpose) on NumPy arrays respectively (doc: docs/emit_python.md)

### Requirement: NumPy-backed runtime shim
The system SHALL provide a Python runtime shim mirroring the C runtime's `matlab_*` API that emitted modules import at run time.

#### Scenario: Running emitted Python
- **WHEN** the emitted module is executed with the shim on `PYTHONPATH`
- **THEN** the `rt.*` helpers SHALL supply MATLAB-semantics behavior (display formatting, builtins) the emitter cannot express inline (src: runtime/shim/matlab_runtime.py)

### Requirement: Parity testing against goldens
The system SHALL verify Python output by running it under the shim and comparing stdout against goldens, honoring per-test skip and override markers.

#### Scenario: Python run lane
- **WHEN** the `run-tests-emit-python` lane runs a program
- **THEN** the system SHALL emit Python, execute it with the shim, and diff stdout (tolerance-aware) against `.stdout` or `.stdout-python`, skipping `.skip-emit-python` cases (src: CMakeLists.txt; src: test/Run/run_tests_emitpython.sh)

### Requirement: Whole-diagram Python emission
The system SHALL, when given a `.mflow` model without a subsystem selector, emit a top-level `simulate()` function that runs the diagram and returns per-sink log arrays.

#### Scenario: Emitting a whole diagram
- **WHEN** `matlabc -emit-python model.mflow` runs on a whole model
- **THEN** the system SHALL emit a `simulate()` function returning the diagram's logged outputs (src: tools/matlabc/main.cpp; src: test/Flowchart/EmitSubsystem)

### Requirement: Documented experimental limitations
The system SHALL treat the Python backend as experimental, rejecting unsupported features such as Symbolic Math at emit time.

#### Scenario: Symbolic input
- **WHEN** a program uses Symbolic Math operations
- **THEN** the system SHALL reject them at emit time rather than emitting incorrect Python (doc: docs/emit_python.md; src: lib/MLIR/Passes/EmitPython.cpp)
