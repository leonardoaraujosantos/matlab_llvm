## Frontend And Sema

- [`sema.md`](sema.md): tour of `lib/Sema/` — bindings, scopes, name resolution, and type inference

- [`flowchart_schema.md`](flowchart_schema.md): `.mflow` JSON schema reference — field-by-field contract, every block kind's required data fields and port conventions, validation rules. **Read this when implementing the IDE save/load.**
- [`mflow_link_roadmap.md`](mflow_link_roadmap.md): **mflowLink** — the compiler-side plan for a Simulink-like *signal-flow* dialect of `.mflow` (time-domain block-diagram simulation). **Greenfield / not started.** Covers schema acceptance, the `MflowLinkModel` lowering (`lib/Flowchart/SignalFlowLowering.cpp`), `runtime_mflowlink.cpp` (sample-time scheduler + ODE-solver wrapping + zero-crossing + snapshot ring), the `-simulate` DAP-server flag, `-emit-mflowlink-cpp`, and the DAP protocol extensions. - [`mStateflow_roadmap.md`](mStateflow_roadmap.md): **mStateflow** — hierarchical Stateflow-style state-chart authoring + live-debug surface as a third `.mflow` dialect (`settings.kind = "state_chart"`) alongside `control_flow` and `signal_flow`. **Compiler / debugger / DAP / REPL side shipped end-to-end** (Tiers 0 / 4 / 6 + partial 8 / 9 / 10); the UI/UX track (Tiers 1–3 / 5 / 7) is the next slice. Chart IR + lowering (JIT-friendly persistent-scalar form + synthesizable HDL form), C++ chart interpreter, full `stateChart/*` DAP namespace (events, requests, introspection, state-enter / state-exit / transition / symbol-change breakpoints), six MathWorks §6.8 canonical fixtures + Moore / Mealy / AND-parallel examples that emit verilator-clean SystemVerilog. See [`../examples/stateflow/`](../examples/stateflow/).
- [`save_load_compat.md`](save_load_compat.md): plan to bring `save` / `load` to the real MATLAB API and `.mat` v5 file format

- [`any_shape_roadmap.md`](any_shape_roadmap.md): **Arbitrary-shape (N-D) array support — 🟡 partial / plan** (core-compiler feature, not a toolbox). Maps where the matrix model stands today (2-D `matlab_mat` + arbitrary-depth 3-D `matlab_mat3`, RAM-bound — `300×200×4` already works for `zeros`/indexing/`size`) and what's needed for full MATLAB-faithful N-D. **Three tiers**: Tier A (small) make arbitrary-depth 3-D fully first-class (N-ary `cat(3,…)`, type-based 3-D tracking that survives expressions, depth-aware ops, trailing-singleton drop); Tier B (medium) 3-D `reshape`/`permute`/`squeeze`/`cat(dim,…)`/dim-3 reductions; Tier C (large) true rank-N arrays via a new `matlab_matN { ndims, dims[], strides[], data }` descriptor + pervasive Sema/Lowering/runtime/REPL-DAP plumbing. Includes the **"nothing broke" testing plan** — baseline the suite on `main` (currently 465/465), gate every change green, add a depth/shape gating sweep, and cross-validate values against NumPy/PIL/MATLAB. Recommends shipping Tier A now and deferring Tier C until a concrete 4-D workload (DL `NCHW` / RGB video / hyperspectral) justifies it.
